---
title: Loading states
description: Skeletons that promise the shape of what's coming.
---

Loading states should preserve layout and user orientation while data is being fetched.

## Default policy

- Prefer **skeletons** for page/section content loading.
- Use **spinners** for in-progress user actions (submit, save, retry).
- Avoid swapping between radically different loading layouts and final layouts.

## Timing guidance

- If expected load is very short, avoid flashing a skeleton for a single frame.
- For longer loads, keep skeleton shape close to final content.
- Keep motion subtle; honor `prefers-reduced-motion`.

## Do / don't examples

- **Do:** show PLP card skeletons with the same card dimensions as final items.
- **Don't:** show a centered spinner for full-page catalog loads.
- **Do:** show button-level spinner while an action is being submitted.
- **Don't:** freeze the whole page for a local action that can be scoped.

## Implementation notes

Use component-level primitives where available (`skeleton`, loading variants) and keep token usage consistent with surrounding surfaces.
