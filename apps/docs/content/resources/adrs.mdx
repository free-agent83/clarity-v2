Architecture decision records (ADRs) capture the load-bearing technical and process decisions behind Clarity V2 — what was decided, why, and what was considered and rejected. They live inline in the architecture document for proximity to the systems they govern.

## Current ADRs

- **[ADR-001 — Bespoke build script over Style Dictionary](../guides/architecture/architecture#adr-001-bespoke-build-script-over-style-dictionary-april-2026)** — why the token pipeline is a ~200-line Node script instead of Style Dictionary.
- **[ADR-002 — Chromatic removed](../guides/architecture/architecture#adr-002-chromatic-removed-april-2026)** — December 2025 security incident, plan for self-hosted visual regression.
- **[ADR-003 — Tokens Studio rejected](../guides/architecture/architecture#adr-003-tokens-studio-rejected-original-decision-retained)** — why bidirectional Figma sync is not the answer.
- **[ADR-004 — Fumadocs over Zeroheight](../guides/architecture/architecture#adr-004-fumadocs-over-zeroheight-april-2026)** — why this site exists.

New ADRs are appended to the architecture document under `## ADRs`. Each one documents context, decision, alternatives considered, and consequences.
